# GitHub firmware specification checklist

- [x] Repository creation, linking, repeat publication, reopening and build artifacts have observable outcomes.
- [x] Acceptance covers stale branches, existing files, invalid projects and failed authorization.
- [x] Offline editing, ZIP export, pinned ZMK output and onboarding have explicit requirements.
- [x] The three success criteria can be exercised independently of implementation details.
- [x] Use GitHub App authorization and record its bounded network and service exceptions in ADR 0028.
