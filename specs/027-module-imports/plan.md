# Plan

Domain and generators each expose one public API because their responsibility groups have mutual dependencies when treated as barrels. Keep those groups as internal folders. Catalog and storage expose their independent groups. UI workspaces and shared UI areas expose separate APIs; move UI composition, project state, preferences, downloads, navigation, shortcuts, dialogs and issue data into distinct modules to avoid composition cycles. Use exact alias-to-index paths in tsconfig.json, shared by Vite and lint. Add an Oxlint JS rule for module boundaries and extend resolved layer checks to follow named barrel re-exports. Use unchanged unit/golden/browser contracts for runtime validation and tests-first fixtures for the new rules. No new user journeys or changed ZMK output.
