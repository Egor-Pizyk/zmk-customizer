## Technical context

Существующие TS7 strict, React19, Vite, Tailwind4, Vitest/Playwright, Node24/Docker. Новых runtime-зависимостей нет. Единственная библиотека сцены — уже принятый в 038 exact JointJS core. Worker — локальный inline bundled browser asset, без сети/CDN и без JointJS; domain/generators остаются синхронными, без Worker/DOM imports.

Текущая schema 13; планировать 14 после сверки интегрированной базы. Текущие бюджеты 512 keys/600 wires/3000 segments против SC-004 500/2000: необходим измеряемый пересмотр wires до 2000 и effective segments до 16000, сохраняя 5 MiB, 64 bends/wire, 8192 crossings и 512 keys. Это новые верхние границы, не обещание принять любой их декартов продукт: совокупные ограничения продолжают действовать. Перед расширением пройти отдельный baseline/stress gate; не менять SC-004 на отказ по лимиту. При невозможности выполнить бюджет — открытый blocker, не ослабление критерия.

Эталон SC-004: production Chromium в существующем Playwright Docker image, один worker, 4 CPU/8 GiB лимит контейнера, host Apple M1 Pro или быстрее; при первом выполнении записать точный host/OS/browser/image digest/limits. 20 измеряемых запусков каждой операции после одного прогрева; nearest-rank p95, end-to-end от нажатия до готового preview, включая structured clone, проверку и первый готовый scene. Фикстура 500 keys/2000 wires/200 insulated crossings, 10% locked: whole-schematic Prettify существующих, в том числе незавершённых проводников; regeneration выбранной матричной области 8×8 в этом полном окружении, с 16 доступными реальными GPIO и фиксированными объектами вне области. Перестраиваемые провода входят в исходные 2000, а replacement не превышает новый budget. Исходные маршруты в обрабатываемой области намеренно неоптимальны; допустимый preview содержит ненулевые геометрические изменения, а no-change не заменяет нагрузочный сценарий. Дополнительно измерить whole-schematic generation на крупнейшем электрически допустимом preset теми же20 samples/p95<=3s и отдельно проверить честный GPIO refusal всей 500-key схемы. Это точные области SC-004, а не замена полной оптимизации500/2000 частичной. Не изобретать GPIO ни для 500-key direct, ни для matrix; capacity-refusal не считается успешным performance preview. Основные два stress кейса должны давать допустимый candidate, не ранний отказ.

## Scope and preserved contracts

Все FR-001–021, US1–5, AC-01–17; этапы из spec не отдельные поставки. Не менять ключи ради симметрии. Prettify сохраняет свободные концы, контакты/ветвления, невалидность/незавершённость, GPIO и экспорт, не только множества key-pin nets. Изоляция пересечений сохраняется семантически: сохранившиеся события remap при изменившихся ordinals, исчезнувшие insulated events удаляются из CrossingRef, новые непреднамеренные crossings изолируются. Electrical equivalence сравнивает раздельность/намеренные branch contacts, не число insulated geometry events. Сохранять anchors, inline/pool contacts, encoder endpoints и pushKey ownership. Обычная ручная проводка с историческими default-connected crossings остаётся совместима; только новые маршруты изолируют непреднамеренные пересечения явно.

История generic; политика запретов в domain, provider только вызывает её до принятия commit. Undo/Redo восстанавливают целые ранее принятые проекты; подтверждённые New/Open используют существующий replace. Нельзя обходить замок составной правкой unlock+delete. Legacy scan/экспорт не меняется при открытии или выборе стиля.

## Constitution check

**Before research:** ограничения поддерживаются; обнаружены два owning-rule конфликта для согласования при реализации: «domain operations apply even if conflict» против явного atomic lock refusal 040 и «only async import/ZIP» против cancellable расчёта. Они не дают разрешения на обход правил.

**After design:** решение соответствует принципам: чистый доменный proposal и Result/refusal по существующему прецеденту 033; локальный UI Worker не вводит backend, runtime dependency или новый источник данных. До production edits уточнить owning `typescript.md`/`react.md`/`admin-ui.md`: protected edits возвращают atomic refusal, существующие обычные validation edits остаются total; UI Worker допускается только для bounded proposal work, с busy/cancel и cleanup. Принятые ADR не переписывать. При необходимости нового ADR по resource/worker решению выделить следующий свободный номер при реализации и обновить owning rules; новый пакет не нужен.

## Design and ownership

### Domain: lock policy below editing modules

В `src/domain/wires/protection/` добавить `validate-wire-protection.ts` и `set-wire-locked.ts`, отдельный типизированный запрос для UI (какой wire защищает объект). Policy зависит только от типов, низкоуровневой геометрии и leaf contacts API; `getWireHalf` принадлежит wire geometry, а геометрические контакты — `domain/wires/contacts`, не от keys/editing, wiring/editing или полного net analysis, чтобы не создать цикл. Сравнивать исходный и полный кандидат: locked wire по ID, поля/route, разрешённые pooled contacts, непосредственные pin/junction/terminal/connected-crossing отношения и реальные положения прикреплённых пинов, meaning терминала и board. Не сравнивать всю net: сосед на общей матрице остаётся свободным. Новое присоединение к locked wire также требует unlock.

Dedicated unlock меняет только locked у явно названных wires. Defensive commit guard допускает unlock-only candidate; unlock с любой другой геометрической/электрической правкой отвергается. Включение/снятие lock — обычный один commit; не preview.

Покрыть public operations `keys/{set-key-geometries,remove-key,remove-keys,remove-keys-and-sections,edit-layout}.ts`, `wires/editing/{set-wire-bends,set-wire-end-board-pin,remove-wire,remove-wire-sections,add-wire}.ts`, orphan cleanup, `wiring/editing/edit-wiring.ts`, controller/layout replacement, diode и encoder edits/crossing insulation. Групповые команды сначала строят полный unchecked кандидат внутри owner module, затем проверяют один раз; не собирать частичный результат из поэлементных отказов. Сохранить внешние Project-returning APIs с no-op на отказ, рядом query даёт issue; Result APIs возвращают structured failure. Provider `applyHistoryAction` повторно вызывает pure policy до autosave, не реализует её самостоятельно и не переносит её в generic history reducer.

### Domain: routing, electrical checks and scope

`src/domain/wiring/editing/` владеет `create-wiring-proposal.ts`, `regenerate-wiring.ts`, `prettify-wiring.ts`, `apply-wiring-proposal.ts` и небольшими peer helpers по мере необходимости. Публичные named APIs через существующий index. `wires/nets/` владеет независимым от route builder каноническим описанием электрических отношений; `analysis/` добавляет UI-safe descriptors для подсветки/недостающих соединений. Runtime UI не импортирует net/matrix engine: shared `getProjectAnalysis` из provider-owned `ui/project/logic/project-analysis.ts` остаётся единственным UI мостом, Worker вызывает только высокоуровневую proposal operation. Добавить эту точную возможность в architecture gate, не разрешать произвольный analysis UI API.

1. Зафиксировать immutable base, выбранные IDs/half/net descriptors и boundary attachments. Scope resolves в domain; partial wire снаружи не разрезать молча, считать boundary фиксированным либо отказать с предложением расширить scope.
2. Regenerate получает целевые assignments отдельно от геометрии: сохранить известные логические ячейки/валидные pins, для пустого/неназначенного проекта использовать существующий явный auto-assign как proposal и показать новые назначения. Не группировать уже назначенную матрицу заново по Y. Direct upper pin2 → input, lower pin1 → GND; отдельные paths до общего GND terminal своей половины.
3. Matrix bus: центры — rotated geometric key centers; медиана Y каждой логической строки своей половины. Distinct sorted heights → ближайший строго верхний ряд/средний положительный интервал; fallback1u. Половина шага даёт row bus. Колонки straight по pin X при совпадении, иначе extreme-X наружу +0.15u, mirrored справа. Зафиксировать roundU 0.0001u и tolerance существующей geometry, не сравнивать floating equality иначе. Mirror axis vertical `xU`, по умолчанию середина между bounds половин; пользовательское значение сохраняется. Наклонные оси не требуются для left/right split.
4. Lock/electrical/clearance constraints выше aesthetics. Перебрать наружные смещения от 0 до 64 шагов `offsetU`; затем прямоугольные detours по видимым координатам препятствий плюс clearance (не более 128 кандидатов на span). Препятствия — чужие pins, fixed attachments и запрещённые overlap/parallel-clearance участки. Перпендикулярные crossings допустимы с явной изоляцией, зазор параллелей не применяется в общей точке намеренного соединения. Силуэт keycap не электрическое препятствие и сам по себе не повод объявить route невозможным; сохранять читаемый выход из пина, без переноса клавиши.
5. Для зеркальных входов оценивать в normalized outward-local coordinates половины, стабильный logical axis/key ID order. Score lexicographic: симметрия/одинаковость, crossing count, bends, length, затем normalized coordinate sequence. Для tie не использовать порядок объектов JointJS, время или worker completion. Ограниченный поиск исчерпан → actionable failure, не утверждение абсолютной невозможности. Оптимизировать локальным spatial segment index, построенным внутри вызова; не вводить persistent caches в Project.
6. Prettify меняет пути существующих wires, сохраняет IDs и структуру их references; не запускает assignment/diode/GPIO operations. Intentional junction/contact sites разрешено перемещать только согласованно со всеми участниками области, fixed free ends остаются на месте. В противном случае site — boundary/fixed. Нет объединения/удаления wires как shortcut оптимизации. Сравнить electrical signature и полную матрицу/scan order до и после. Вернуть исходный Project при точном no-op, в том числе после второго запуска; settings-only commit не является «нулевым результатом» и показывается явно.
7. Перед готовым proposal проверить lock policy, scoped out-of-scope equality, electrical equivalence для Prettify, ресурсы, shorts/diode/resource errors для regeneration. Инварианты независимы от score route builder. Существующие errors разрешены в Prettify только без ухудшения/изменения электрического смысла. Blockers и advisory warnings разделены; геометрическая warning не блокирует экспорт сохранённого проекта.

### Domain/storage: settings and migration

См. [data-model.md](data-model.md). `Project.routing` хранит только serializable настройки и желаемые назначения для незавершённых проектов, не derived graph. `Wire.locked?: true` — отсутствие равно unlocked. v13→v14 сохраняет все проводники/значения, добавляет только версию, новые defaults получаются чистым query без регенерации. Legacy смешанные pin/diode состояния показывать «Смешанное» на основании фактических связей, не выдумывать uniform state. Desired assignments никогда не подменяют реальные nets при validation/export.

В storage заморозить v13 schema до расширения current, валидировать её checkpoint до migration, зарегистрировать v14 и все limits одинаково в domain/storage/JSON schema/package for agents. Оба матричных действия используют существующий KeyDiode, один на key: физический diode pin = rowPin для diodeSide=row, противоположный для col. Pin swap сохраняет diodeSide, diode transfer сохраняет rowPin; оба сохраняют `diodeDirection`. Пересчитать cathode по row/col flow и физической стороне, показать физические изменения в preview; при замке отказать целиком. Пин1 — нижний локальный, пин2 — верхний по текущему Cherry geometry; старый direct был input1/GND2, поэтому только явная новая регенерация меняет это, migration ничего не переподключает.

### UI: proposal lifecycle and projection

Расширить `use-wiring-preview.ts` и существующий preview coordinator, не заводить второй draft manager. Состояния idle/calculating/ready/stale/refused. Base Project остаётся оригинальной ссылкой в UI; Worker возвращает typed changed/no-change/refused reply без commit; только changed содержит clone candidate + summary. Worker reply имеет discriminant `kind: changed | no-change | refused` и echo source revision/request token на transport envelope. `changed` содержит candidate и полный diff, включая settings-only; `no-change` не содержит candidate и означает равенство всех применяемых полей, а не только геометрии. Внутри Worker domain по-прежнему возвращает исходную локальную ссылку при no-op, но transport превращает это в no-change. UI никогда не сравнивает Worker clone с main-thread base по ссылке: для актуального no-change сохраняет оригинальный main-thread Project, показывает нулевой summary/disabled Apply, не вызывает commit/autosave. Late no-change проходит те же stale guards. Capture `importSession.getRevision()` из 038 и request token; после любого accepted Project transition токен устарел, даже Undo→Redo/ABA. Проверять base+revision+request перед показом и внутри Apply updater. Не увеличивать второй revision counter. Cancel/новый запрос/editor dismissal terminates Worker, discard late result; unmount cleanup и правило effects обновляются, без новых contexts. При Worker error показать отказ и сохранить проект; неизвестные application errors не глотать generic catch.

Bundled module `ui/schematic/wiring/logic/wiring-worker.ts` принимает typed доверенные Project/board/scope/settings из приложения, выполняет чистую operation; все JSON/file inputs уже прошли storage. Не выполнять JSON parsing в UI. Worker code включён eager static import `?worker&inline` в первоначально загружаемый application bundle, без lazy transport import, внешних/dynamic Worker chunks, fetch/importScripts/CDN. Создание и повторное создание Worker после Cancel использует уже загруженный inline constructor, не HTTP cache или заранее выполненную операцию. Production build должен подтвердить отсутствие внешних Worker dependencies. Текущая `infra/nginx.conf` CSP наследует запрет Blob Worker из script-src; до активации добавить только `worker-src blob:` (без data:, расширения script-src или connect-src). Проверить реальную nginx CSP и Blob lifecycle/cleanup в browser; при создании Worker failure показать отказ, без секундного main-thread fallback. Нет synchronous fallback, блокирующего Cancel. Перед commit перепроверять snapshot invariants по готовым доменным descriptors; тяжёлое O(n²) на main thread не повторять. Лёгкий guard O(size) измерить вместе с Apply; итоговый resource/lock validation обязателен.

Compatibility bridge for existing WiringEdit controls: the Worker replays a transient typed edit transcript against the captured base, retaining the existing consecutive topology-choice source semantics. This preserves pending choices when a newer request supersedes an unfinished edit, and lets explicit Recalculate replay intent against the latest Project. The transcript is not persisted or used as electrical truth; new regenerate/Prettify requests will carry their explicit scoped settings.

`wiring-controls` показывает три варианта в группе topology/style, область и параметры. Глобальные toggles отдельно, с «Вся клавиатура», derived current state + proposed state; direct disabled with reason. Native controls, sticky existing footer, change summary and error links. `parts-wires-table` получает lock buttons и keyboard equivalent. Diagram descriptors показывают lock icon, selected net/row/col и diagnostic missing paths; эти marks не становятся Wire и не сериализуются. Ссылки diagnostics выбирают entity через существующий issues/navigation путь; preview issues отделены от saved Problems/export. Обновить onboarding и связанные targets.

## Verification strategy

Сначала failing independent contracts, затем production code. Замороженные входы и hand-authored expected relations, никаких expected через проверяемый router. Точную requirement → task → check → evidence mapping создать только в tasks.md следующим этапом; здесь тестовые области, а не дублированная task таблица.

- `tests/unit/domain/wires/`, `keys/`, `wiring/editing/`, `diodes/`, `encoders/`: lock bypass matrix, pooled contacts, terminal/board, atomic groups; independent circuit signatures, fixed ends/branches, partial scope, rotated pins, all 8 matrix combinations; deterministic mirror ties и repeated Prettify/no-op.
- `tests/unit/storage/{project,migrations}/`: frozen v13 и все исторические fixtures до v1, malformed fields, unknown/newer refusal, near-byte-budget и expanded-wire/segments budget, Save/Open exact round trip и autosave failure. Старые файлы не меняют геометрию/электрический смысл и получают unlocked semantics.
- `tests/unit/generators/` и независимые fixtures: actual matrix/direct/split output до/после Prettify побайтно; новые pin/diode combinations against pinned v0.3.0 goldens. Невалидные проекты сравнивать по полному circuit/issue смыслу, не по успешному экспорту. При изменённом output — `make zmk-build` по commands, обе topology и оба направления; не заявлять physical hardware verification.
- `tests/unit/ui/{integration,state}/` с real provider: no-op/Cancel/stale/repeated Apply/ABA/in-flight change, один save+Undo, reject lock before autosave, terminate Worker boundary. Mock только платформенный Worker transport в jsdom; настоящий алгоритм — unit и реальный Worker — browser.
- `tests/e2e/symmetric-wiring.spec.ts`: реальные клики/жесты и keyboard table journey, empty/existing regenerate, incomplete Prettify, mixed lock refusal+find wire, toggles/scope, stale/Cancel/Undo/Redo/reload/Open/JSON+ZIP. Exact saved data/output, не DOM-only. Дополнить targeted Firefox/WebKit для focus/Worker/SVG; light/dark и 390/1024/1280 widths, 200% text/reduced motion. Проверить online-load→offline Worker computation без remote resources. Рендеренный до/после UI-review обязателен.
- Отдельный sensitivity run: контролируемо убрать lock check или base revision guard; пользовательская/saved assertion должна упасть, восстановить точные файлы; не запускать вместе с другими checks.
- SC-004 measurable gate и repeat routing: протокол [quickstart.md](quickstart.md), логи в ignored paths, evidence в journal. Профилирование не разрешает снижать correctness/clearance/locks или считать ранний refusal успехом.
