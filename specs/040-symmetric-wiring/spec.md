# Feature Specification: Симметричная генерация и оптимизация проводки

## User scope revision — remove Prettify (2026-10-29)

Latest explicit user decision supersedes all earlier Prettify requirements and acceptance in this specification: remove Prettify entirely from the current product. No button, keyboard action, preview operation, domain/Worker command or onboarding recommendation remains. Generate wiring and its read-only Apply/Cancel, locks, scope, Undo/Redo, persisted settings and existing project data remain supported. Do not replace generation with optimization or mutate projects during removal. Prettify is deferred for a separately approved future return; historical requirements below describe that postponed work, not a current completion gate.

**Feature Branch**: `feature/040-symmetric-wiring`
**Created**: 2026-10-27
**Status**: Clarified — готово к speckit-plan, реализация не начата
**Input**: Отдельная фича после 038: симметричная генерация, независимый Prettify и защита ручной проводки.

## Goal and scope

Пользователь строит аккуратную проводку без изменения расположения клавиш, улучшает только геометрию существующих соединений и защищает вручную настроенные участки. До изменения проекта он видит результат, электрические последствия и конфликты.

**In scope**: три различимых варианта выбора — существующая матрица, матрица со симметричными шинами, direct с отдельными маршрутами; области обработки, два независимых переключателя матрицы, генерация, Prettify, замки, диагностика, сохранение настроек и доступный предпросмотр. Все описанные возможности обязательны для завершения фичи.

**Non-goals**: перемещение клавиш ради симметрии, автоматическое исправление физического оборудования, новые типы сканирования, PCB-разводка, дифференциальные пары и согласование их длин, реализация на этапе specify. Возможное продолжение: именованные пользовательские пресеты геометрии и сравнение нескольких вариантов маршрутизации; они не входят в обязательный scope.

**Existing contracts to preserve**: offline, клавиатурный доступ, существующие данные, история и детерминированный экспорт для ZMK v0.3.0. Project — единственный сериализуемый источник истины. Расчёт топологии и маршрутов чистый, неизменяемый и детерминированный; JointJS отображает и передаёт действия, его граф, anchors и router не определяют электрическую связность. Изменения формата требуют миграций и тестов старых файлов; runtime-зависимости — ADR. Это ограничения совместимости, не выбор реализации.

**Dependency and work order**: 038 остаётся отдельной фичей, её spec не меняется. На старте открыт PR #34; пользователь явно запросил новую ветку от текущей 038 с включением main, что является осознанным исключением из начала от origin/main и разрешением второго активного направления. После подготовки и анализа артефактов пользователь 2026-10-27 явно поручил начать реализацию, зная об открытом PR038. Это разрешение параллельной реализации на явно зависимой ветке; слияние/поставка040 остаются после интеграции038. До PR 040 его основание должно быть согласовано с интегрированной 038 без включения чужих изменений как части 040. Открытые #29 и #31 требуют повторной проверки перед реализацией; они не объявлены автоматически зависимостями поведения. Номер 039 уже занят `039-focused-local-checks` в удалённой ветке; resolver подтвердил 040 при явном предпочтении следующего свободного номера. Релизная принадлежность не назначается автоматически.

## Clarifications

### Session 2026-10-27

- Q: Как подключать два маршрута от каждой клавиши в direct? → A: Верхний локальный пин идёт отдельным маршрутом к индивидуальному GPIO, нижний — отдельным маршрутом к общему GND-терминалу своего контроллера/половины. Возвраты объединяются только у этого терминала; общей геометрической шины между клавишами нет. Один GPIO на клавишу; межконтроллерные соединения автоматически не добавляются. Поворот клавиши сохраняет назначение локальных пинов.

- Q: На какую область должны действовать кнопки перестановки пинов и переноса диодов? → A: Оба переключателя действуют на всю клавиатуру атомарно. При любом конфликте, включая замок или несовместимость одной половины, вся операция отклоняется. Разные настройки по половинам/выделению этими кнопками не создаются. Выбранная область ограничивает только генерацию и Prettify.

- Q: Как определять положение рядов для шин при stagger и thumb cluster? → A: Одна шина на логическую строку каждой половины. Высота центра ряда — медиана вертикальных координат центров её клавиш; для чётного числа клавиш — среднее двух центральных значений. Ряд выше — ближайший центр строго выше. «Вверх» означает вверх на схеме; поворот отдельной клавиши меняет положение пинов, но не направление шин. Совпадающие высоты разных логических строк не объединяют цепи; при невозможной геометрии нужен объяснимый обход либо конфликт.

- Q: Какие исходные интервалы и отступы использовать для новой разводки? → A: Запасной межрядный интервал 1u, отступ колоночной шины 0,15u, минимальный зазор параллельных маршрутов 0,10u; 1u = 19,05 мм. Значения изменяемы в настройках проекта. Для верхнего ряда берётся среднее расстояние между соседними различающимися высотами рядов своей половины; если таких расстояний нет — запасной интервал. Шина проходит на половине интервала выше центра ряда. Колоночное смещение направлено наружу: влево для левой половины/unibody, вправо для правой половины split.

- Q: Что делать, если предпочтительная симметричная разводка не помещается или конфликтует с замками? → A: Сначала сдвигать шину наружу с шагом заданного отступа, затем добавлять прямоугольные обходы. Минимальный зазор не уменьшается, электрический смысл и замки сохраняются. Симметрия может нарушаться только с предупреждением. Среди допустимых обходов приоритеты: симметрия и единообразие, меньше пересечений, меньше изгибов, короче маршрут. Выбор повторяемый. Если допустимого результата нет — отказ всей операции.

## User scenarios and acceptance

### US1 — Создать предсказуемую симметричную проводку (P1)

1. На пустой или заполненной схеме пользователь выбирает вариант, область и настройки и запускает «Сгенерировать заново»; видит read-only предложение с заменяемыми, сохраняемыми и добавляемыми проводами/диодами до Apply.
2. На регулярной сетке шинный стиль даёт отдельные ответвления к общей шине строки и прямые колонки; электрические назначения совпадают с выбранной матрицей.
3. На зеркальном split одинаковые входные назначения и зеркальная геометрия дают зеркальные маршруты относительно выбранной оси; асимметричная половина не принуждает другую к неверной электрической связи.
4. Для direct у каждой клавиши два отдельных маршрута: от верхнего локального пина к индивидуальному GPIO, от нижнего к общему GND-терминалу своего контроллера/половины без общей шины между клавишами; расход GPIO равен числу входов, а не двум на клавишу. При нехватке ресурсов Apply недоступен и перечислены недостающие ресурсы по контроллеру.
5. При конфликте с замком или невозможном маршруте проект остаётся целиком исходным; видны причина и ссылка на соответствующие объекты.

### US2 — Улучшить существующую геометрию (P1)

1. На частично соединённой схеме Prettify улучшает существующие маршруты; отсутствующие связи остаются отсутствующими и обозначены отдельно без фиктивных проводов.
2. После Apply сохраняются состав цепей, намеренные контакты, идентичность подключённых пинов и терминалов, свободные концы, изоляция пересечений, GPIO, матрица, диоды и положение клавиш. Конфигурация ZMK до/после побайтно одинакова для экспортируемого проекта.
3. Для неэкспортируемого проекта сохраняется электрический смысл, включая незавершённость и электрические ошибки; Prettify не маскирует их достроенными связями.
4. Повторный Prettify применённого результата предлагает ноль изменений и не создаёт шаг истории. Пустая схема сообщает «Нет существующих соединений для оптимизации».

### US3 — Защитить ручной участок (P1)

1. Замок провода включается на схеме и в списке мышью или клавиатурой, имеет доступное имя с идентификатором провода и видимое состояние.
2. Заблокированный провод нельзя переместить, изменить его изгибы/концы, удалить или переподключить ни напрямую, ни массовой командой, ни регенерацией. Только явное снятие замка снимает защиту.
3. Попытка перемещения/поворота/изменения размера непосредственно присоединённой клавиши, меняющая защищённое соединение, отклоняется; показаны причина и команда найти защищающий провод.
4. Группа из свободной и защищённой клавиш не перемещается частично. Соседняя клавиша на той же общей цепи, непосредственно не соединённая с защищённым проводом, остаётся редактируемой.
5. Reload и Save/Open сохраняют замки; Undo/Redo точно восстанавливает их и геометрию. Старый проект открывается со всеми проводами без замков.

### US4 — Независимо изменить пины и размещение диодов (P2)

1. Для матрицы две отдельные кнопки «Поменять пины строк и колонок» и «Перенести диоды: строки / колонки» доступны клавиатурой и показывают текущее/предлагаемое состояние и область «Вся клавиатура». Обе операции применяются ко всей клавиатуре атомарно.
2. Проверяются все четыре сочетания: нижний пин строковый/колоночный × диоды на строках/колонках; дополнительно каждое с обоими поддерживаемыми направлениями тока. Перестановка пинов сохраняет выбранную логическую сторону диодов (строки / колонки) и направление сканирования. Если строка/колонка переходит на другой физический пин, физический пин диода пересчитывается, чтобы сохранить ту же логическую сторону; это не отдельное переключение стороны диодов. Перенос диодов меняет только логическую сторону, сохраняя назначение пинов и направление сканирования.
3. Перенос сохраняет электрически допустимую полярность выбранного направления, не дублирует существующие диоды; предпросмотр, настройки и экспорт согласованы.
4. Если изменение хотя бы на одной половине делает конфигурацию несовместимой или требует изменения защищённого соединения, Apply запрещён для всего предложения, с объяснением. Выделение не сужает область переключателей: она явно обозначена как вся клавиатура.

### US5 — Понять предложение и безопасно применить его (P1)

1. Весь путь — выбор области/стиля, оси, отступов, просмотр изменений, поиск конфликта, Apply/Cancel — выполняется клавиатурой и через список объектов без жестов на canvas.
2. До Apply проект, автосохранение и история неизменны; Cancel возвращает исходное состояние. Один изменяющий Apply — один Undo; Undo/Redo восстанавливает весь результат, настройки и защиты. Нулевой результат не добавляет историю.
3. Любое изменение исходного Project, включая Undo/Redo, делает открытый предпросмотр устаревшим и неприменимым; видна команда пересчитать. Переключение темы или масштаба просмотра не меняет Project.
4. Подсветка выбранной строки, колонки или цепи согласована между схемой и списком; пропущенные связи, предупреждения и замки различимы без опоры только на цвет.

## Requirements

- **FR-001 (US1)**: Показывать три различимых варианта. Существующая матрица и шинная матрица — два стиля одной матричной топологии: один и тот же набор логических ячеек, row/col GPIO и направления диодов не меняется от выбора стиля. Direct — отдельная топология, не матрица из соседних клавиш.
- **FR-002 (US1)**: Существующая матрица соединяет строковые и колоночные цепи; direct — индивидуальные входы и общий GND своей половины. Текущая автоматическая разводка строит индивидуальные пути к терминалам с различающимися отступами и проверяет контакты/изоляцию; текущий direct отвергает диоды. Новые стили не обязаны сохранять старые неравномерные отступы. Открытие проекта сохраняет существующую электрическую схему.
- **FR-003 (US1)**: Для direct использовать поддерживаемый v0.3.0 принцип «один вход GPIO на клавишу и возврат GND», без предположения о двух GPIO. Проверять пригодность, занятость и резервирование GPIO, включая другие устройства, отдельно на каждом контроллере. Верхний локальный пин соединяется отдельным маршрутом с индивидуальным GPIO, нижний — отдельным маршрутом с общим GND-терминалом своего контроллера/половины. GND-маршруты объединяются только у этого терминала, без общей геометрической шины между клавишами. Поворот сохраняет назначение локальных пинов. Межконтроллерные соединения автоматически не добавляются. Диодные/матричные переключатели в direct показывать неприменимыми с причиной.
- **FR-004 (US1, US4)**: По умолчанию нижний локальный физический пин клавиши строковый, верхний колоночный; при повороте идентичность локальных пинов сохраняется, а не определяется заново по экранному Y. Логические строки/колонки берутся из назначения матрицы, не из визуального соседства; пропущенная позиция не создаёт клавишу или электрическую связь.
- **FR-005 (US1)**: В шинном стиле от строкового пина каждой клавиши идёт короткое ответвление вверх к общей горизонтальной шине логической строки. Шина находится посередине между центром текущего физического ряда и ряда выше. Для верхнего ряда берётся среднее положительных расстояний между соседними различающимися высотами рядов своей половины. Если таких расстояний нет (один ряд или все центры на одной высоте), используется запасной интервал по умолчанию 1u. Шина верхнего ряда проходит на половине выбранного интервала выше центра ряда. Между текущим и ближайшим строго верхним центром шина проходит посередине. Выход шины направлен влево, на правой половине split зеркально вправо. На каждой половине используется одна шина на логическую строку, даже при нескольких визуальных группах и thumb cluster. Высота центра ряда — медиана экранных вертикальных координат центров клавиш логической строки (при чётном количестве — среднее двух центральных значений). Ряд выше — ближайший центр строго выше; «вверх» направлено вверх на схеме независимо от поворотов отдельных клавиш. Совпадающие высоты разных строк не объединяют цепи; геометрический конфликт требует объяснимого обхода или отказа.
- **FR-006 (US1)**: Колонки с совпадающими координатами соответствующих пинов по возможности соединяются прямой вертикальной линией. При stagger/разных координатах используется общая смещённая вертикальная шина и короткие ответвления ко всем нужным пинам. Колоночное смещение направлено наружу: влево на левой половине и unibody, вправо на правой половине split. Исходный отступ 0,15u, одинаковый в сопоставимых ситуациях; минимальный зазор параллельных маршрутов по умолчанию 0,10u. По умолчанию диоды находятся на строковой стороне, в колонке диодов нет; существующий проект не меняется от открытия новых настроек.
- **FR-007 (US1)**: Неравномерные ряды, thumb clusters, повороты, нестандартные размеры, пропуски, одна колонка и разные половины не меняют логическую матрицу ради геометрии. Если идеальная шина нарушает ограничения, предложение показывает объяснимый обход и нарушенную геометрическую цель либо блокирующий конфликт. Сначала проверяется предпочтительная геометрия; при конфликте проверяются сдвиги шины наружу с шагом заданного отступа, затем прямоугольные обходы. Минимальный зазор не уменьшается; электрический смысл и замки сохраняются. Допустимое нарушение симметрии отмечается предупреждением. Среди допустимых вариантов применяются приоритеты FR-008; равнозначные случаи разрешаются повторяемо, зеркально для зеркальных входов. Если допустимого результата нет, вся операция отклоняется без частичного применения. Prettify не достраивает связи, а недостижимость новой геометрии не даёт права менять клавиши или замки. Случайные электрические контакты недопустимы.
- **FR-008 (US1, US2)**: Приоритеты строго упорядочены: электрическая корректность и замки; допустимые маршруты; зеркальность и единообразие; сокращение пересечений, изгибов и длины. Клавиши не перемещаются. Разные цепи не объединяются; геометрическое пересечение само по себе не создаёт контакт. Одинаковые ситуации получают одинаковые отступы и форму ответвлений.
- **FR-009 (US1, US5)**: Область обработки: вся схема, выбранная половина, выбранные клавиши/цепи. Предпросмотр перечисляет фактические объекты области и граничные связи. Объекты вне области и их связность сохраняются; если без их изменения операция невозможна, отказ с предложением явно расширить область. Автоматического расширения нет. Переключатели назначения пинов и стороны диодов всегда действуют на всю клавиатуру атомарно, независимо от области генерации/Prettify; эта область явно показана у переключателей.
- **FR-010 (US1)**: Генерация заново работает и на пустой, и на заполненной схеме, перестраивает выбранную топологию/стиль в области, сохраняет защищённые объекты и показывает для существующих проводов и диодов «заменить/сохранить», для новых — «добавить». Неизвестные аппаратные назначения нельзя молча выдавать за факты; новые назначения явно представлены как предложение.
- **FR-011 (US2)**: Prettify изменяет только маршруты, отступы, положение изгибов и симметрию существующих проводников. Не создаёт отсутствующих электрических соединений и не меняет GPIO, матрицу, направление/сторону диодов или клавиши. Сохраняет точный электрический смысл, а не только количество цепей: наборы участников каждой цепи, ветвления, намеренные контакты, незавершённость и изоляцию. Положение неподключённых свободных концов сохраняется как пользовательское намерение. Если изолированное геометрическое пересечение исчезает, его ненужная запись изоляции удаляется при сохранении раздельности проводников; для сохранившихся пересечений изоляция переназначается на новое событие, для новых непреднамеренных — создаётся. Намеренный электрический контакт не исчезает вместе с изменением геометрии.
- **FR-012 (US1–US5)**: Любая генерация, Prettify или инверсия сначала создаёт read-only предпросмотр. Apply доступен только для актуального, целиком допустимого предложения; Cancel не меняет проект. Замок включается/снимается явной обычной правкой с Undo, без отдельного preview. При конфликте запрещено применять повреждённую или неожиданную частичную часть предложения.
- **FR-013 (US3)**: Замок защищает идентичность, маршрут, изгибы, конечные точки и непосредственные контакты провода. Нельзя обойти защиту удалением/заменой терминала, клавиши, диода, переключением топологии, импортом фрагмента или иной массовой правкой в текущем проекте. Явное Open/New с подтверждением замены всего проекта остаётся существующей отдельной операцией, а не скрытым способом редактирования провода.
- **FR-014 (US3)**: Геометрическая правка непосредственно подключённой клавиши разрешена только если защищённое соединение остаётся неизменным. Защита не распространяется транзитивно через всю цепь. Групповое перемещение, поворот, изменение размера, удаление или переподключение атомарны: если хотя бы один участник нарушает замок, вся команда отклоняется; можно явно изменить выделение или снять замок. Для генерации/Prettify заранее обозначенные защищённые объекты могут оставаться неподвижными, если полный результат допустим.
- **FR-015 (US3, US5)**: Замки и настройки разводки сохраняются в Project, reload, Save/Open и Undo/Redo. Старые проекты открываются без замков и без автоматической регенерации. Ошибка миграции/импорта не повреждает текущий проект. Точная сохранённая геометрия не пересчитывается при загрузке.
- **FR-016 (US4)**: Перестановка row/col физических пинов и перенос диодов между row/col независимы и всегда действуют на всю клавиатуру атомарно. Независимость означает сохранение логической стороны диода при перестановке пинов и сохранение назначения пинов при переносе диодов. Физический пин диода вычисляется из этих двух состояний: для стороны row он равен rowPin, для col — противоположному пину; его смена при pin swap показывается в preview. Направление сканирования не меняется; полярность пересчитывается для электрически корректного тока. Разные настройки по половинам/выделению этими кнопками не создаются; конфликт на любой половине, включая замок, отклоняет всю операцию. Направление тока задаётся согласованной настройкой, не угадывается из экранного расположения. Для каждого сочетания сохраняется корректная полярность, нет дубликатов диодов, предпросмотр и экспорт согласованы с v0.3.0; неподдерживаемое сочетание отклоняется целиком с причиной.
- **FR-017 (US1, US5)**: Авторазводка использует единый отступ (по умолчанию 0,15u), минимальный зазор параллельных маршрутов (0,10u), запасной межрядный интервал (1u) и ось зеркальной симметрии split. Геометрические расстояния заданы в u, 1u = 19,05 мм. По уточнению пользователя 2026-10-28 числовые настройки авторазводки не показываются в Wiring: алгоритм выбирает геометрию автоматически, пользователь корректирует провода вручную. Существующие сохранённые значения остаются совместимыми и проходят прежнюю проверку; никаких миграций/скрытой перезаписи. Выбор оси split остаётся отдельным геометрическим требованием следующих этапов. Геометрия проходит предпросмотр.
- **FR-018 (US5)**: Итог предпросмотра содержит числа и доступные списки изменяемых, сохраняемых и защищённых объектов, предупреждений, оставшихся несоединённых пинов; отдельно перечислены короткие замыкания, нехватка GPIO, невозможные маршруты и конфликты замков. Ошибка ведёт к объекту на схеме и в списке; пропущенные связи — диагностический слой, не сохранённые провода.
- **FR-019 (US5)**: Название операции, её область, состояния переключателей и Apply/Cancel постоянно видны при прокрутке панели. Во время расчёта показано состояние занятости, повторный Apply невозможен. После Cancel фокус возвращается к вызвавшей кнопке, после ошибки доступно её объяснение; список обеспечивает альтернативу canvas. На узком экране панель прокручивается без потери действий; light/dark, масштаб текста и reduced motion сохраняют читаемость и доступность. Кандидат, исходная схема и замки различимы формой/подписью помимо цвета.
- **FR-020 (US1, US2)**: Одинаковый Project и настройки дают идентичную геометрию и электрический результат, включая повторную генерацию и после Save/Open; нет зависимости от времени и случайности. Prettify идемпотентен. Нулевой результат и Cancel не добавляют историю; одна применённая операция добавляет ровно один шаг.
- **FR-021 (US5)**: Обновить затронутые шаги onboarding, названия/цели обучения и инструкции по генерации, Prettify и замкам в этой фиче; старый tutorial не должен вести к заменённым элементам управления.

## Edge cases

Приёмочный набор ниже обязателен; проверка каждого случая включает сохранение объектов вне области и отсутствие случайного контакта.

| ID | Вход / действие | Проверяемый результат |
| --- | --- | --- |
| AC-01 | Регулярная сетка 3×3, шинная генерация | Общие row-шины, индивидуальные ответвления, прямые колонки; назначение не меняется |
| AC-02 | Stagger, ключи разных размеров, повёрнутые 30°/90°, thumb cluster | Локальные пины и логические назначения сохранены; сначала наружные сдвиги с заданным шагом, затем прямоугольные обходы без уменьшения зазора; предупреждение об отклонении от симметрии либо конкретный конфликт |
| AC-03 | Зеркальный split, выбранная ось; затем несимметричные половины | В первом случае зеркальные маршруты, во втором корректные независимые обходы и объяснение отклонений |
| AC-04 | Единственный ряд, колонка, пустоты матрицы, несколько физических рядов логической строки | Одна шина на логическую строку, медиана высот её клавиш; ближайший строго верхний центр и запасной интервал 1u при отсутствии положительных межрядных расстояний; нет фиктивных ячеек и деления на отсутствующий интервал |
| AC-05 | Четыре сочетания row-pin/сторона диодов × row2col/col2row; выделена одна половина; затем конфликт на другой половине | Переключатели явно действуют на всю клавиатуру; конфликт на любой половине отклоняет операцию целиком; независимость логических состояний; физический pin диода равен rowPin для row и противоположному для col; корректная полярность и согласие настроек, схемы и ZMK; нет дубликатов |
| AC-06 | Пустая и полностью/частично заполненная схема, обе топологии и стили | Регенерация показывает точную замену; Prettify не достраивает отсутствующие связи |
| AC-07 | Direct на пределе GPIO и на один вход сверх предела; занятые/резервные пины | Один GPIO/клавиша; верхний локальный пин → индивидуальный GPIO, нижний → отдельный возврат к GND-терминалу своего контроллера; нет общей шины между клавишами и автоматических межконтроллерных связей; точная диагностика по контроллеру, атомарный отказ сверх предела |
| AC-08 | Намеренный T-контакт, провод через промежуточный пин, свободный конец и изолированное пересечение | Prettify сохраняет каждое отношение до/после, даже после reload и Undo/Redo |
| AC-09 | Замок, прямое редактирование, массовое удаление/переподключение, смешанная группа | Запрещённые команды целиком отклонены; защищающий провод найден; сосед по цепи не блокируется транзитивно |
| AC-10 | Регенерация/Prettify рядом с замком, затем несовместимое назначение | Защита сохранена; допустимый обход показан либо Apply запрещён целиком |
| AC-11 | Все области, цепь пересекает границу выделения | Вне области данные и контакты неизменны либо объяснимый отказ, без скрытого расширения |
| AC-12 | Cancel, нулевой результат, Apply→Undo→Redo, изменение источника при preview | Ноль/ноль/один шаг соответственно; точное восстановление; устаревший результат не применяется |
| AC-13 | Save/Open, reload, старые файлы | Геометрия, замки и настройки сохранены; миграция старых без замков; ошибочный файл не заменяет проект |
| AC-14 | Два запуска на одинаковом входе; второй Prettify | Идентичный результат; второй Prettify ничего не меняет |
| AC-15 | Экспортируемые matrix/direct до/после Prettify, обе половины | Все генерируемые файлы конфигурации побайтно одинаковы; ключевые электрические назначения независимо сравнены |
| AC-16 | SC-004: whole-schematic Prettify500/2000, selected8×8 regeneration в том же окружении; whole-schematic generation крупнейшего допустимого preset | Допустимые preview укладываются в бюджет; outside-scope unchanged; Cancel работает, нет промежуточных правок. Full500 GPIO refusal проверяется отдельно и не заменяет успешный preview |
| AC-17 | Клавиатура, список вместо canvas, темы и узкий экран | Все действия достижимы, состояния озвучиваемы, фокус предсказуем, действия preview видны |

Неверные назначения матрицы, неоднозначные физические ряды, невозможные зазоры и существующие короткие замыкания показываются как конкретные проблемы. Prettify не исправляет электрические ошибки скрыто; генерация может предложить исправление только как явное электрическое изменение в preview. Геометрическое совершенство не оправдывает нарушение более высокого приоритета.

## Key entities

- **Настройки разводки**: стиль геометрии, область, отступы/зазор, ось split и независимые состояния матричных переключателей.
- **Защищённый провод**: существующая идентичность провода, его замок и непосредственные защищённые контакты; это не замок всей цепи.
- **Предложение изменения**: операция, исходное состояние, область, кандидат, различия и диагностика; до Apply не является сохранённым проектом.
- **Электрическая цепь и граничный контакт**: намеренная связность пинов/терминалов/ветвлений, независимая от изображения и пересечений.

## Success criteria

- **SC-001**: Для 100% AC-01–AC-17 соблюдены заявленные инварианты; ноль незапрошенных соединений, потерянных контактов и изменений защищённых объектов.
- **SC-002**: Для всех экспортируемых приёмочных проектов Prettify сохраняет 100% байтов генерируемой конфигурации. Для незавершённых проектов сохраняется точная электрическая связность и несоединённость.
- **SC-003**: Для повторных одинаковых входов результат одинаков; второй Prettify даёт ноль изменений. Cancel, устаревший preview и нулевой результат создают ноль шагов истории, изменяющий Apply — ровно один.
- **SC-004**: На зафиксированном эталонном desktop-окружении схема из 500 клавиш, 2000 проводов и 200 изолированных пересечений, включая 200 заблокированных проводов (10%), даёт допустимый preview не более чем за 3 с в 95-м перцентиле 20 запусков каждой операции после одного прогрева. Область нагрузки явно различается: Prettify обрабатывает всю схему; генерация заново перестраивает выбранную матричную область 8×8 в полном окружении 500/2000, с 16 реальными доступными GPIO, сохраняя объекты вне области. В исходные 2000 включены заменяемые провода; candidate остаётся в ресурсных лимитах. Исходные маршруты в обрабатываемой области намеренно неоптимальны; допустимый preview содержит ненулевые геометрические изменения, а no-change не заменяет нагрузочный сценарий. Отдельно генерация всей схемы проверяется на крупнейшем электрически допустимом preset с тем же бюджетом <=3 с; невозможную по GPIO полную схему500 проверяют на атомарный диагностируемый отказ, который не засчитывается вместо допустимых preview. Apply/Undo/Redo — не более 500 мс, отклик Cancel — не более 200 мс. Время включает передачу данных, проверки и готовность отображённого preview; окружение, версия браузера, область, fixture и все samples записываются в evidence. Отказ по старому лимиту проводов не заменяет выполнение этих сценариев.
- **SC-005**: 100% действий US1–US5 доступны только клавиатурой и через альтернативу canvas; сохранённый результат соответствует отображённому и экспортируемому.

## Assumptions and open questions

### Подтверждённая база

Проверенные [kscan notes](../../docs/zmk/kscan.md) задают matrix row2col/col2row и direct с одним входом и GND. Шинная матрица не новый драйвер. Текущий direct не поддерживает диоды. Эти факты не требуют нового аппаратного предположения; правила direct, геометрии и области переключателей согласованы в пяти ответах выше. Перед изменением генерации заново читаются relevant verified docs/zmk, нужны независимые fixtures/golden и проверка сборки по правилам проекта.

Материальные вопросы текущего clarify закрыты. При планировании нужно определить проверяемые границы поиска маршрутов, точное правило разрешения равнозначных кандидатов и эталонное окружение SC-004; это детализация реализации, не разрешение ослабить зазоры, симметрию, электрические инварианты или атомарность. Исчерпание ограниченного поиска должно честно диагностироваться как невозможность построить предложение при данных настройках, а не доказательство физической невозможности проводки.

Числовые координаты относятся к системе проекта; «вверх на схеме» не зависит от pan/zoom. Различающиеся ряды сравниваются по этим координатам. Предпочтительная смещённая колоночная шина располагается снаружи диапазона соответствующих пинов на заданном отступе; при совпадении их X приоритет имеет прямая линия FR-006. Совпадающие по высоте строки остаются разными цепями и проходят обычную проверку конфликтов/обходов FR-007.

### Обязательный MVP и дальнейшие этапы внутри 040

1. **MVP — безопасность и базовая ценность**: preview/Apply/Cancel и актуальность, замки со всеми обходными путями и persistence/migration, атомарная история, whole-schematic регенерация шинной матрицы и Prettify существующей геометрии, сохранение электрического смысла, базовая диагностика и доступный список. Это промежуточный этап, не завершение 040.
2. **Этап 2 — полный набор топологий и управления**: симметричный direct с принятым подключением GPIO/GND, независимые переключатели для всей клавиатуры, все области с граничными контактами, сохранённые настройки и подсветка/недостающие связи.
3. **Этап 3 — нерегулярная геометрия и окончательная приёмка**: полная согласованная нерегулярная геометрия, ось split, асимметрия, все сочетания и края, измерение производительности, браузерные/визуальные проверки, onboarding и полный набор AC. Базовые согласованные правила геометрии применяются уже в MVP.

Все этапы остаются обязательными в одной фиче и одной поставке по Git flow. Для планирования потребуются requirement-linked проверки domain/storage/generator и изолированные браузерные сценарии реальных операций со сравнением сохранённого JSON/экспорта. Рендеренный UI-review и проверка чувствительности нового взаимодействия выполняются на этапе реализации; сейчас таких доказательств нет.

### Уточнение компактного Wiring — 2026-10-28

В основном Wiring остаются scanning type, topology, применимая diode direction, matrix routing style, scope и реальные GPIO. Все поля относятся к одной форме без отдельной обведённой секции Generate/ Routing. Числовые отступы/зазор/fallback убраны из UI. Подбор rows/columns, логическая сетка и таблица клавиш доступны в одном свёрнутом «Manual assignments», сохраняя ручную настройку и доступ к ошибкам. На этапе обучения GPIO нужные поля остаются видимыми.

Действия расположены сразу под заголовком Wiring, вне прокрутки полей. Одна строка действий: **Generate wiring** (основная кнопка) и **Prettify** (вторичная). Rebuild удалена как дублирующий пользовательский путь, а не переименована в Prettify. Generate создаёт/заменяет проводку с reviewable preview, Prettify меняет только геометрию сохранённых соединений. Для historical direct Generate сохраняет поддерживаемый legacy генератор до отдельного нового direct алгоритма; временная unsupported choice не появляется. При активном preview основной кнопкой становится Apply. Короткое пояснение различает две операции; Cancel/no-op/stale/Undo/Save/Open и защита остаются прежними.

Приёмка: основная форма не содержит Rebuild/числовых routing settings/отдельного Routing fieldset; Generate и Prettify рядом доступны с клавиатуры; manual assignments открываются и редактируются, GPIO-проблема раскрывает нужное поле. Обе темы и 1024×768 сохраняют видимые действия preview; обучение использует Generate и объясняет Prettify. Изменение длины вывода шины из оборванного пункта5 ожидает уточнения; до него геометрия не меняется.

### Уточнение по образцам и видимости пинов — 2026-10-29

Ответ пользователя: «Между рядами; сократить выводы и выровнять вертикальные шины». Это подтверждает FR-005: row bus остаётся между логическими рядами, отдельные короткие ответвления несут диоды; горизонтальная линия через нижние пины на ручном образце не является новой электрической топологией. Для symmetric-bus короткие выводы rows направлены наружу от половины, на общей вертикали: отступ от внешней границы клавиш2,5u (вдвое меньше прежнего левостороннего5u), одинаково зеркально для split. Повороты и размеры учитываются по реальным границам клавиш. Полные электрические названия/GPIO доступны в списке; короткие R/C labels позволяют не разносить колонки ради текста. Применение через preview; сохранённые GPIO/логическая матрица, lock/scope guards и явная insulation сохраняются.

Каждая клавиша продолжает показывать оба физических пина, их номера и доступные hit targets во время wire preview, после соединения/прохождения провода через один пин, изменения диода, Undo/Redo и reload. Изменение SVG-структуры не может переносить сбрасываемые атрибуты от старого text/circle на новый group. Это уточняет существующие003 US1/US2 и038 FR-004, не меняет электрическую модель или spec038.

Matrix generation always uses Symmetric matrix buses. Remove Routing style and the existing-style generation alternative, including typed routing dispatch branches. ## Automatic Matrix GPIO assignment — 2026-10-29

Automatic Matrix construction on a scan-mode or topology change assigns available
controller GPIOs to every row/column terminal in the preview, just as Generate does.
A separate Generate click is not required to turn drawn buses into assigned circuits.
Retain valid existing terminal assignments; exclude occupied encoder/manual GPIOs;
split halves have independent controller namespaces. Insufficient resources or invalid
retained assignments refuse the whole proposal without modifying the source/history.
Manual pin clearing and project Open remain explicit/manual operations; neither
silently assigns pins. Existing preview/Apply/Cancel/Undo/export contracts remain.
This supersedes earlier expectations that mode/topology previews leave GPIO unassigned.
