## Performance protocol and budgets

For each revision, fresh browser context per navigation sample, identical preloaded fixture/preferences; measure navigation through two requestAnimationFrame callbacks. Record first load separately; take at least three warm samples. Focus k1 and alternate Shift+ArrowRight/Left five times, timing each action through two callbacks. Assert a real accepted move/save and alternating xU 0↔0.25, not merely a painted selection. Use medians and preserve every sample/failure. These end-to-end wall-clock timings include automation overhead and are not frame/FPS measurements.

Adoption gates: warm-load and nudge medians each <=1.25× the same-environment paired baseline; first navigation <=2 seconds on the baseline environment. Corrected planning medians are 676.17ms load and159.95ms nudge (reference ceilings845.21ms /199.94ms); the later paired repeat is recorded separately in verification.md. Remeasure base on changed environments; do not loosen the 25% regression limit because of a slower implementation. Repeat a failing pair to distinguish environmental variance and retain both outcomes; do not discard failures to obtain a pass.

Separately measure input-to-second-animation-frame callback latency in pinned Chromium; this is a scheduling/render-opportunity proxy, not actual paint latency. Before app handlers, a test-only capture-phase native pointermove listener records performance.now(), then schedules nested requestAnimationFrame callbacks and records the second callback performance.now() minus the entry timestamp. A sample counts only after its second callback completes; count every delivered event without debounce, retain raw samples, and do not drop slow/missing samples. For each gesture scenario, load the untouched large fixture at1440×900, then activate Zoom in exactly six times in both revisions. This exposes actual corner targets that are covered by higher-priority pin/end targets at100% zoom. Assert the real painted target and selected key/whole-wire before measurement; do not benchmark an occluded proxy. Use20 warm-up moves excluded explicitly, then100 measured moves at20ms spacing for each of single-key drag, multi-key drag, corner drag and pan, on the same large fixture, viewport, zoom, semantic target/coordinates and scripted out/back motion for both revisions. If needed references/coordinates differ, resolve by stable semantic entity IDs and record world/screen endpoints. p95 is sorted sample at index ceil(0.95*N)-1 per scenario; require each migrated p95<=1.25× its paired base. An undelivered/incomplete scenario is an invalid measurement, never a pass.

In the same controlled windows (first measured move through last second-frame callback), use PerformanceObserver longtask entries from the application top-level document and require no task duration>200ms. This budget covers all application main-thread work, including domain calculations; no renderer-only attribution is claimed. Preserve trace+samples for diagnosis (copy test-results before the next Playwright run clears them), measure base under the same rule and report a failing base explicitly; do not waive the absolute budget. Run 25 workspace/project/history cycles separately, asserting one live scene/listener set and no duplicate commit. Browser frame traces and the historical profiler review remain separate from this callback metric. The historical 003 profiler 16ms expectation is not established by these navigation/nudge timings: retain its review, report baseline failures explicitly and resolve any conflicting acceptance in its owning spec before completion. No claim of 60fps follows from this protocol.

## Production bundle protocol

T002 records the base build inventory; T048 measures final cost only after integration and old-scene cleanup. Build both revisions with their own locked dependencies, identical Node/Vite configuration and minification settings. For every emitted runtime JS/CSS file under dist, record path, raw bytes and bytes after gzip level9 (same Node gzip implementation); sum raw and per-file-gzip totals separately for JS and CSS, and report final-minus-base totals. Include lazy chunks; report other runtime assets and any licensing artifact separately. Retain manifests/build logs and exact SHAs in ignored logs. Do not confuse npm unpacked size, unused installed packages, dev bundles or only the entry chunk with runtime cost. A measured delta is required evidence, not an invented size acceptance limit.

## Acceptance journeys

1. **No-write inspection:** Open ordinary/rotated/split/direct/diode/encoder/invalid/legacy fixtures. Pan, zoom, select and switch workspaces. Compare saved JSON and generated bytes with base, assert invalid export stays blocked. Inspect geometry/labels and absence of duplicate encoder push art.
2. **Gesture history:** Place/move/rotate, draw a pin/free/junction wire and drag a derived corner. Each completion is one Undo and exact Redo; no-op, refusal, Escape, pointercancel/lost capture and duplicate completion produce zero additional writes. New/Open/Undo→Redo during a draft makes late events harmless.
3. **Electrical parity:** Independently move A/B/C in a pass-through circuit; test insulated versus connected crossings, overlap and multiple crossings per pair. Verify partitions, saved contacts and unchanged unrelated routes after reload. Diagram geometry must match independent expected points, not an imported copy of its own projection output.
4. **Precise removal:** Select both sides of an L-shaped connected crossing; Shift/marquee mix keys/sections; delete once and preserve independent fragments/controller ends. Undo/reload and use dense-crossing list alternatives. Verify whole-wire bend highlight remains distinct.
5. **Preview isolation:** Rebuild, topology round trip, Apply/Cancel and stale proposal invalidation. Inspect/select in preview, refuse mutations, scroll nested panels while Apply/Cancel remain visible. Download actual ZIP and compare accepted contents with preview.
6. **Accessible shared surface:** Pointer and keyboard paths in Chromium, targeted Firefox/WebKit; current role/names/focus and native text keys; both themes at every spec viewport plus 200% equivalent reflow, low zoom and reduced motion. Bindings retains shared camera behavior. Actual screen-reader/mouse-free/OS zoom review remains manual acceptance.
7. **Offline/onboarding/recovery:** Disable network after loaded assets, run real 3×3 onboarding through ZIP. Induce a classified renderer failure: accepted data/history and save controls survive, Retry rebuilds current state. Repeat mount/unmount/project/history cycles without duplicate scenes/listeners/commits. Domain programmer error still reaches root boundary.

## Required commands and delivery

During implementation stage explicit paths and run `npm run check:changed`; for the committed branch use `npm run check:changed -- --base origin/main`. Full CI owns comprehensive suites; targeted direct runs are diagnostic with a recorded reason. Use isolated Playwright through terminal under [testing](../../docs/testing.md), never a normal browser/CUA session. Manual checks must be recorded separately. No firmware build is required for unchanged generator output; if output changes, reopen scope and follow pinned-reference/build gates. Complete tasks/analysis/implementation stages before the single feature PR; do not publish this plan as proof of adoption.


The executable protocol is tests/e2e/jointjs-performance.spec.ts and its fixtures/diagram-latency.ts and diagram-timings.ts helpers. Copy only this harness to the isolated base checkout; application code/dependencies stay at their own revisions. For a base run set SCHEMATIC_BASELINE_RUN=true; record SCHEMATIC_REVISION and SCHEMATIC_IMAGE_ID in both environments. Preserve each scenario latency.json under a stable directory as single-key.json, multi-key.json, corner.json and pan.json, plus timings.json. For the implementation run set SCHEMATIC_BASELINE_LATENCY to that directory and SCHEMATIC_BASELINE_TIMINGS to the paired timings.json. Browser/Node and screen/world references are checked before comparing the25% budgets. Without paired receipts, a run establishes only absolute/sample/data-isolation gates. SCHEMATIC_PROFILE=true collects a separate20-sample CPU diagnostic, never adoption evidence. Navigation/nudge samples use default zoom; gesture windows use the six-step zoom above. No concurrent test or profiling workload during a timed run.
