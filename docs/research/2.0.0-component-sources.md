# 2.0.0 component model and dimension sources

Research date: 2026-10-21. Scope: reusable sources for full-height MX-compatible Gateron, KS-33 Low Profile 2.0, matching keycaps, Pro Micro, nice!nano v2 and possible nRF52840 alternatives. Supports the [2.0.0 roadmap](../roadmap-2.0.0.md) and [discovery journal](2.0.0-discovery.md).

## Finding

Useful partial libraries and manufacturer CAD downloads exist. No single inspected source establishes complete, accurately dimensioned, redistribution-cleared coverage of the requested component set. In particular, official Gateron STEP downloads were confirmed; nice!nano v2's exact mechanical model remains unconfirmed. “Not found” below is limited to this search, not proof that a resource does not exist.

A file's existence, model accuracy, reuse permission and physical fit are separate statuses. No source below has been physically validated for this product. No external model is imported into the app by this task.

## Remaining adoption work

- Use Gateron's exact KS-33 and chosen full-height STEP/drawings as the first mechanical references, subject to matching revisions and permission checks. Combine partial sources rather than relying on one universal library.
- Confirm nice!nano v2 mechanics and each selected clone independently; board outline alone omits USB position, solder, wire exit and component envelopes.
- Select actual cap sets/rows/sizes and validate stem engagement plus full-travel skirt/wall clearance. A shared cross-shaped stem does not establish compatibility. No exhaustive manufacturer-verified KS-33-compatible cap library was found.
- Keep visual mesh, CAD body, authoritative dimensions and clearance/mounting rules as separate records. Footprints can corroborate pin/plate geometry without proving whole-body fit.
- Before bundling, record per-file source URL, revision/hash, SKU, units/axes/origin, license/attribution, transformations and evidence status. Preserve licenses for derived assets. Bundle only approved pinned assets; no runtime catalog fetch is proposed.
- Run the already planned fit sample and full reference-assembly checks. CAD download/header verification does not establish closed valid solids, exact tolerances, printability or physical fit.

## Evidence and limits

Root research and two independent source reviews inspected official pages, repository trees, selected source/license files and selected archives. GitHub API rate limiting eventually stopped additional tree queries; existing results and direct source pages remain recorded. Broad marketplace search produced possible models but did not establish better verified provenance; aggregators are not treated as primary CAD evidence.

Root downloaded the two Gateron archives to ignored external `/tmp/zmk-component-research/`, listed them with `tar -tf`, and read extracted file headers without executing supplied code. SHA-256: KS-33 archive `cbe39795bad5c94514e99078d1f94d69e81359d3f80eda3dcc27017b8f55fbce`; KS-3X archive `50f7a696bcade26cfacd0a3391b9dfded5c9c68632e1907a51c4318af30073b8`. These checks establish delivered file identity/type only. No CAD viewer/kernel import, dimensional extraction, printing or hardware validation was performed. Upstream links may change; pin the selected artifacts during adoption. Verification for this documentation revision is recorded in PR #18, with the discovery task journal.
